# Tab "Trade" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** aggiungere al tracker una tab "Trade" che, per gli oggetti scelti, calcola casse, viaggi, giorni e gold per ottenere i materiali lavorati col commercio, con un registro consegne che affina i rapporti.

**Architecture:** logica pura nel blocco `<script id="core">` di `index.html` (testata in Node con `tests/load-core.js`); dati in un nuovo `data/trade.json` scritto a mano, caricato da una funzione separata `loadTrade` (non tocca `loadData`); il registro consegne vive nell'oggetto progress come campo opzionale `deliveries`; l'interfaccia è una tab nella colonna centrale.

**Tech Stack:** HTML + JS senza build, `node:test`, Playwright (solo per verifica manuale, già in `scraper/node_modules`).

**Spec:** `docs/superpowers/specs/2026-11-19-trade-tab-design.md` (approvato). Deviazione dal §5 dello spec, decisa qui: in `trade.json` ogni avamposto ha `families: [...]` (array) e non `family`, perché Shadow Path ne ha due (`archeum`, `stone`); lo spec va allineato nel Task 6. Seconda deviazione: `tradePlan` non riceve `items` (basta l'id del passo, via `tradeInfo`), quindi la firma è `tradePlan(trade, steps, deliveries, opts)` e non `tradePlan(items, steps, trade, deliveries, opts)` come nello spec §5.

## Global Constraints
- Un solo `index.html`, JS senza build; logica pura nel blocco `core` con test `node:test`.
- Il repo pubblico resta "solo codice": `trade.json` contiene solo osservazioni dell'autore, nessun dato MetaForge.
- Autore dei commit: noreply (identità già impostata nel repo); trailer `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; **push solo su richiesta**.
- Interfaccia in inglese di base, italiano selezionabile (`STRINGS.en` e `STRINGS.it` con le stesse chiavi: lo verifica `tests/i18n.test.js`).
- Layout che regge a 380 px, senza scorrimento orizzontale.
- Ogni rapporto mostrato è etichettato "stima" oppure "dal tuo registro (n consegne)" (anti-obiettivo dello spec: numeri che sembrano precisi ma sono ipotesi).
- Suite completa: `node --test 'tests/*.test.js' 'scraper/tests/*.test.mjs'` (oggi 122 test, 0 fail).

## Review Focus
Input e condizioni che lo spec implica ma i test dei task non esercitano di default; ogni riga ha il test nel task indicato.
1. Rapporto `null` (superior senza dati): la riga è "dato mancante", resta fuori dai totali, nessun `NaN`/`Infinity` → Task 3.
2. Unità da ottenere = 0 (coperte da `have`): nessuna riga → Task 3.
3. Famiglie diverse allo stesso avamposto (Shadow Path: archeum + stone) condividono i viaggi: `ceil(somma casse / 7)` → Task 3.
4. Registro corrotto o file di progresso vecchio senza `deliveries`: voci non valide scartate, il file resta valido → Task 2.
5. `trade.json` assente o malformato: la tab mostra "dati non disponibili" e il resto dell'app funziona → Task 4 (loader) e Task 5 (UI).

### Task 3: `tradePlan`

**Files:**
- Modify: `index.html` (nuova `tradePlan`, export), `tests/trade.test.js`

**Interfaces:**
- Consumes: `tradeInfo`, `effectiveRatio` (Task 1-2); `steps` di `computeNeeds` (`{id, need, covered, times, …}`).
- Produces: `tradePlan(trade: Trade, steps: Step[], deliveries: Delivery[], opts: {tripsPerDay: number}) -> {groups, notTradeable, totals}` con
  `groups: [{post: string, name: string, lines: Line[], packs: int, trips: int}]` (ordine degli avamposti di `trade.posts`, solo quelli con righe),
  `Line = {id, tier, family, units: int, ratio: number|null, source: 'estimate'|'log', n: int, missing: boolean, packs: int|null, input: int|null, gold: int|null}`,
  `notTradeable: [{id, units}]`, `totals: {packs, trips, days, gold}`.
- Regole: `units = need − covered` (salta se ≤ 0); `packs = ceil(units / (ratio × pack.input))`, `input = packs × pack.input`, `gold = packs × pack.gold`; ratio `null` → `missing: true` e `packs/input/gold` `null`, fuori dai totali; `trips` per gruppo = `ceil(Σ packs del gruppo / limits.perTrip)`; `totals.trips = Σ trips dei gruppi`, `totals.days = ceil(totals.trips / opts.tripsPerDay)` (0 se nessun viaggio), `totals.gold = Σ gold`, `totals.packs = Σ packs`; `notTradeable` = passi il cui id ha prefisso livello (`/^(standard|fine|superior)-/`) ma `tradeInfo` è `null` (ossa); gli altri passi (l'oggetto finale ecc.) sono ignorati.

  - `'unità già coperte da have: nessuna riga'` → `step('standard-ingot', 100, 100)` → `groups: []`, `totals {packs 0, trips 0, days 0, gold 0}`.
  - `'le ossa vanno in notTradeable, l oggetto finale è ignorato'` → `standard-bonecraft 729`, `gyldenlords-cleaver 1` → `notTradeable [{id:'standard-bonecraft', units:729}]`.
  - `'usa il rapporto del registro quando c è'` → consegna fine ingot `input 21, received 42` → ratio 2 con `source 'log'`; Fine Ingot 45 → `ceil(45/(2×3)) = 8` casse.
